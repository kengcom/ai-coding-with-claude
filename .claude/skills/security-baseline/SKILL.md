# Security baseline: น้ำท่วมไหม

ทุก spec และทุก PR ต้องผ่านกฎทุกข้อด้านล่าง ถ้าข้อไหนทำตามไม่ได้ ให้เขียนเหตุผลลง spec แล้วถามเจ้าของงานก่อน ห้ามข้ามเงียบๆ
ตอนอ้างกฎให้ใช้รหัส เช่น `SEC-03`

## ระบบภายนอก

- **SEC-01** ห้ามส่งคำขอที่เปลี่ยนข้อมูล (POST PUT PATCH DELETE) ไปที่ระบบรายงานน้ำท่วมจริง เช่น `flood-api.rooptanjai.com` ทั้งในโค้ด ใน test และในสคริปต์ ใช้ได้แค่ GET และ test ต้องใช้ข้อมูลปลอมเสมอ
- **SEC-02** ห้ามเพิ่ม dependency ที่ใช้ตอนรัน ห้ามเรียกบริการภายนอกที่เสียเงิน ใช้แค่สิ่งที่มากับ Node 22

## ข้อมูลที่รับจากผู้ใช้

- **SEC-03** ตรวจทุกช่องที่รับเข้ามาที่ขอบของระบบ (`handle()`) ทั้งชนิด ช่วงค่า และความยาว ช่องที่ไม่รู้จักให้ทิ้ง ห้ามส่งต่อหรือเก็บ · ดึงช่องที่รู้จักออกมาทีละช่อง ห้ามใช้ `Object.assign` หรือ `{...body}` กับข้อมูลจากผู้ใช้
- **SEC-04** ถ้าข้อมูลผิด ให้ตอบ `400` พร้อมชื่อช่องที่ผิด ห้ามส่งค่าที่ผู้ใช้กรอกกลับไปในข้อความ error และห้ามแสดง stack trace
- **SEC-05** ข้อความที่ผู้ใช้พิมพ์ต้องจำกัดความยาว ปฏิเสธอักขระควบคุม (U+0000–U+001F และ U+007F) **ก่อน**ตัดช่องว่างหัวท้าย แล้วจึงตัด · ส่งกลับได้เฉพาะในรูป JSON ห้ามนำไปประกอบเป็น HTML SQL shell หรือ regex
- **SEC-06** จำกัดขนาด body ของคำขอที่ server (ค่าเริ่มต้น 10 KB) ถ้าเกินให้ตอบ `413` และหยุดอ่านทันที

## การใช้งานเกินควร

- **SEC-07** endpoint ที่เขียนข้อมูลต้องจำกัดจำนวนคำขอต่อผู้ส่ง ถ้าเกินให้ตอบ `429` · ตัวนับต้องมีเพดานจำนวน key หรือล้างของที่หมดเวลาแล้ว เพื่อไม่ให้หน่วยความจำโตไม่หยุด
- **SEC-08** ใช้ IP จาก socket เท่านั้น ห้ามเชื่อ header `X-Forwarded-For` จนกว่าจะมี proxy ที่เรากำหนดเอง · ปรับรูป IP ก่อนใช้เป็น key: ตัด `::ffff:` ของ IPv4-mapped ออก และนับ IPv6 ตามช่วง /64

## ข้อมูลส่วนบุคคล (PDPA)

- **SEC-09** เก็บข้อมูลเท่าที่จำเป็น ห้ามเก็บชื่อ เบอร์โทร อีเมล หรือพิกัดของคนส่ง ถ้าไม่มีข้อตัดสินใน `docs/intent/` รองรับ
- **SEC-10** IP ใช้ได้ 2 อย่างเท่านั้น คือนับโควตา และจับว่าคนเดิมส่งรายงานซ้ำ ทั้งสองอย่างต้องอยู่ในหน่วยความจำของตัวจำกัดจำนวนคำขอ และหมดอายุตามรายงาน · ห้ามเก็บ IP ลงข้อมูลหลัก ห้ามส่งออกใน API ห้ามลง log และห้ามอยู่ในข้อความ error
- **SEC-11** log ห้ามมี body ของคำขอ ข้อมูลส่วนบุคคล หรือ token ใดๆ ให้ log แค่ method, path, status และเวลาที่ใช้

## การแสดงผล

- **SEC-12** ทุกคำตอบ `2xx` ของ API ต้องมี `NOTICE` ว่าเป็นตัวอย่างเพื่อการเรียน ไม่ใช่ประกาศเตือนภัยทางการ
- **SEC-13** ข้อมูลจากประชาชนต้องแยกจากข้อมูลสถานีวัดเสมอ และติดป้ายว่า "ยังไม่ยืนยัน" ห้ามรวมเป็นค่าเดียวกัน

## Test

- **SEC-14** กฎ SEC-03 ถึง SEC-12 ที่ spec หรือ PR แตะ ต้องมี test ที่พิสูจน์ได้ อย่างน้อยข้อละ 1 test ที่เป็นกรณีผิด
