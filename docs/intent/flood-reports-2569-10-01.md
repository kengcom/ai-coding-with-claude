# Intent: รายงานจุดน้ำท่วมจากคนในพื้นที่

> สรุปจากการ grill 8 ข้อ วันที่ 1 ต.ค. 2569 · เริ่มจากศูนย์ ไม่ได้อิง `docs/intent/flood-reports.md` ฉบับเดิม (ไฟล์เดิมยังอยู่)
> repo นี้เป็นตัวอย่างสอน ข้อมูลเป็นข้อมูลสมมติ ไม่ใช่ระบบเตือนภัยทางการ

## Problem

ตอนนี้ "น้ำท่วมไหม" บอกได้แค่ระดับน้ำจากสถานีวัด ซึ่งมีไม่กี่จุดต่อเขต และวัดระดับน้ำในคลอง ไม่ใช่น้ำบนถนน
คนที่จะออกจากบ้านหรือเลือกเส้นทางอยากรู้ว่า **ถนนหรือซอยที่ตัวเองจะผ่านท่วมลึกแค่ไหนตอนนี้** ข้อมูลนี้คนที่อยู่ตรงนั้นเห็นอยู่แล้ว แต่ไม่มีที่ให้ส่ง และคนอื่นไม่มีที่ให้ดู

ผู้ใช้สองกลุ่ม:
- **ผู้รายงาน** — คนในพื้นที่ที่เห็นน้ำท่วม อยากบอกเขต จุดสังเกต ความลึก และเวลาที่เห็น โดยไม่ต้องสมัครสมาชิก
- **ผู้ดู** — คนที่กำลังตัดสินใจ อยากเห็นรายงานล่าสุดของเขตนั้น แยกจากข้อมูลสถานีให้ชัด และรู้ว่าเป็นข้อมูลที่ยังไม่ได้ตรวจ

## Proposed outcome

### ทำเสร็จแล้วอะไรเปลี่ยน

- มี `POST /reports` รับ `{ districtId, landmark, depthCm, seenAt }` คืน `201` พร้อมรายงานและ `notice: NOTICE`
- `GET /districts/:id` มี key ใหม่ `reports` — รายงานยังไม่หมดอายุ สูงสุด 20 อันใหม่สุด (เรียงตาม seenAt ใหม่ไปเก่า) แต่ละอันมี `{ id, landmark, depthCm, seenAt, verified: false }` · ของเดิมใน response คงเดิมทุก key
- `GET /districts` ไม่เปลี่ยน

### กติกาที่ตัดสินแล้ว

| เวลาที่นับ | **seenAt** (เวลาที่เห็นน้ำ) · receivedAt บันทึกจาก `ctx.now` ใช้ภายในเท่านั้น | Q2 |

| ไม่แสดงต่อสาธารณะ | receivedAt · IP | Q7 |

### วัดผลยังไง

**ด้านเทคนิค — เงื่อนไขของคำว่า "เสร็จ"** (ทุกข้อ grep หรือรันตรวจได้)
- `npm test` ผ่านทั้งหมด · `tests/app.test.ts` และ `tests/time.test.ts` เดิมผ่าน**โดยไม่ถูกแก้** (`git diff main -- tests/app.test.ts tests/time.test.ts` ว่าง)
- มี test ครอบขอบของทุกกติกา: depth `0` `1` `300` `301` · seenAt พอดี 6 ชม. และ 6 ชม. + 1 วิ · อนาคต 5 นาที และ 5 นาที + 1 วิ · landmark ยาว 120 และ 121 · รายงานที่ 6 ใน 10 นาทีได้ `429` · รายงานที่ 21 ไม่แสดง
- `npm run lint` ผ่าน · `dependencies` ใน `package.json` ยังไม่มี (ไม่เพิ่ม runtime dependency)
- ไม่มี IP ใน response body และ log · log มีแค่ method, path, status, เวลาที่ใช้
- รัน `npm run dev` ส่ง `curl -X POST http://localhost:3000/reports` จริง แล้ว `GET /districts/:id` เห็นรายงานนั้น — ส่งได้แค่ localhost เท่านั้น

**ด้านประโยชน์ — ถ้าใช้จริง (ยังไม่มีตัวเลขเป้า ดู Open questions)**
- เวลาที่รู้เร็วขึ้น: ช่วงห่างระหว่างรายงานแรกของประชาชนในเขต กับตอนระดับสถานีข้ามเกณฑ์
- อัตรารายงานที่ถูกปฏิเสธ แยกตามเหตุ (`400` แต่ละแบบ `429`) — บอกว่ากติกาเข้มหรือหลวมไป · นับเป็นจำนวน ไม่เก็บเนื้อหา

## Constraints

### ความปลอดภัย (อ้างรหัสใน `.claude/skills/security-baseline/SKILL.md`)
- **ห้ามส่ง POST/PUT/PATCH/DELETE ไประบบรายงานน้ำท่วมจริง** เช่น `flood-api.rooptanjai.com` ทั้งในโค้ด test และสคริปต์ อ่าน (GET) ได้อย่างเดียว (`SEC-01`)
- IP ใช้ได้แค่ในตัวจำกัดจำนวนคำขอในหน่วยความจำ ห้ามเก็บคู่กับรายงาน ห้ามลง log ห้ามอยู่ในข้อความ error ห้าม hash เก็บไว้ (`SEC-10`)
- log มีได้แค่ method, path, status, เวลาที่ใช้ (`SEC-11`)
- ห้ามปนรายงานประชาชนกับข้อมูลสถานี — key แยก (`reports` ≠ `stations`) ชื่อแยก (`depthCm` ≠ `levelCm`) (`SEC-13`)
- landmark เป็นข้อความอิสระที่แสดงต่อสาธารณะทันที ต้องผ่านกติกาใน Q4 ทุกครั้ง

### งบและเทคโนโลยี
- งบเป็นศูนย์ ไม่มีบริการภายนอก ไม่มี CAPTCHA/OTP
- ห้ามเพิ่ม runtime dependency ใช้แค่ที่มากับ Node 22 (`SEC-02`) — `node:sqlite` ยังไม่ใช้เพราะยัง experimental
- เวลาทั้งหมดใน logic มาจาก `ctx.now` ห้าม `new Date()` (รวมตัวจำกัดจำนวนคำขอ)
- ตรรกะอยู่ใน `handle()` ใน `src/app.ts` · `src/server.ts` เพิ่มได้แค่การจำกัดขนาด body และส่ง IP เข้า context

### กฎของ repo และคอร์ส
- คำตอบ 2xx ทุกตัวต้องมี `notice: NOTICE` คำตอบ error ไม่ต้องมี
- ความลึกเป็นจำนวนเต็มหน่วยเซนติเมตร เวลาเก็บ UTC แสดงผล +07:00

### สิ่งที่ห้ามแตะ
- `data/stations.json`
- รายชื่อ 12 เขตใน `src/districts.ts`
- `tests/app.test.ts` `tests/time.test.ts` (ห้ามแก้ให้ผ่าน)
- พฤติกรรมเดิมของ `GET /districts` และ `GET /districts/:id` (เพิ่มได้แค่ key `reports`)
