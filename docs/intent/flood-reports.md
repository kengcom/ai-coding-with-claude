# Intent: ให้คนในพื้นที่รายงานจุดน้ำท่วม

> สรุปจากการ grill 8 ข้อ วันที่ 30 ก.ย. 2569 · ยังไม่มีโค้ด
> แก้ 30 ก.ย. 2569 หลังรีวิว spec: IP ใช้จับรายงานซ้ำด้วย · นับความยาวเป็น code point · ตัด `observedAt` ไม่ให้เกิน `receivedAt` · ใส่ `NOTICE` เฉพาะคำตอบ `2xx` · ปุ่มช่วยเลือกความลึกเลื่อนไปรอบถัดไป
> ตัวอย่างเพื่อการเรียนเท่านั้น ไม่ใช่ระบบเตือนภัยทางการ

## Problem

ตอนนี้ แอปน้ำท่วมไหมแสดงแค่ระดับน้ำจากสถานีวัดในแต่ละเขต (`GET /districts/:id`) ซึ่งมีปัญหาดังนี้

- สถานีวัดระดับน้ำในคลอง ไม่ได้วัดน้ำบนถนน คนที่จะออกจากบ้านจึงไม่รู้ว่าถนนหน้าปากซอยหรือหน้าห้างท่วมแค่ไหน
- บางเขตไม่มีสถานีเลย เช่น สายไหม ซึ่งคืนรายการสถานีว่าง
- คนในพื้นที่เห็นน้ำท่วมกับตาก่อนใคร แต่ไม่มีที่ให้บอกต่อ

## Proposed outcome

คนในพื้นที่ส่งรายงานจุดน้ำท่วมได้ แล้วคนอื่นเห็นรายงานนั้นทันทีในหน้าข้อมูลของเขต

### ตัดสินแล้ว

| เรื่อง | ข้อตัดสิน |
| ------ | --------- |
| ตำแหน่ง | ใช้ `districtId` ที่ต้องอยู่ใน 12 เขตของ `src/districts.ts` คู่กับจุดสังเกตแบบข้อความสั้น (ตัดช่องว่างหัวท้าย ยาวไม่เกิน 100 code point ≈ 70–80 ตัวที่ตาเห็นในภาษาไทย) · **ไม่เก็บพิกัด lat/lng** |
| การแสดงผล | ขึ้นแสดงทันที ไม่มีคิวรอตรวจ ติดป้าย "รายงานจากประชาชน ยังไม่ยืนยัน" และแยกจากข้อมูลสถานีวัด |
| ตัวตนคนส่ง | ไม่ระบุตัวตน ไม่มีล็อกอิน ไม่เก็บเบอร์โทร · IP ใช้ 2 อย่าง คือจำกัดจำนวนรายงาน และจับว่าคนเดิมส่งจุดเดิมซ้ำ ทั้งคู่อยู่ในหน่วยความจำเท่านั้น |
| ที่เก็บ | เก็บในหน่วยความจำผ่าน interface `ReportStore` ส่งเข้า `handle()` ทาง `Context` แบบเดียวกับ `now` · รีสตาร์ต server แล้วรายงานหาย ซึ่งรับได้ |
| ความลึก | API รับจำนวนเต็มหน่วยเซนติเมตร 1–200 · ปฏิเสธ 0 ค่าติดลบ ทศนิยม และค่าที่ไม่ใช่ตัวเลข · หน้าจอมีปุ่มช่วยเลือก (ตาตุ่ม ≈ 10 ครึ่งแข้ง ≈ 20 เข่า ≈ 40 เอว ≈ 80) **แต่รอบแรกทำแค่ API** ปุ่มช่วยเลือกเลื่อนไปรอบที่มีหน้าจอ |
| ความรุนแรง | คำนวณจากความลึก: < 20 เล็กน้อย · 20–49 ปานกลาง · ≥ 50 รุนแรง (ตัวเลขรอคนยืนยัน) |
| เวลา | เก็บ `observedAt` ที่คนส่งระบุ (ไม่บังคับ ถ้าไม่ใส่ใช้ `receivedAt`) และ `receivedAt` ที่ server ใส่เอง · ต้องเป็น ISO 8601 ที่มีเขตเวลา (`Z` หรือ `+07:00`) · รับช่วงตั้งแต่ `now` − 6 ชั่วโมง ถึง `now` + 5 นาที · ค่าที่ล้ำอนาคตให้ตัดลงมาเท่ากับ `receivedAt` ก่อนเก็บ · เก็บเป็น UTC แสดงผลด้วย `toBangkokIso` · หมดอายุที่ `observedAt` + 3 ชั่วโมง |
| รายงานซ้ำ | เก็บทุกรายงานแยกกัน แล้วจัดกลุ่มตอนอ่าน · ถือเป็นจุดเดียวกันเมื่อ `districtId` ตรงกัน และจุดสังเกตตรงกันหลังปรับรูปแบบ (ตัดช่องว่างหัวท้าย ยุบช่องว่างซ้ำ แปลงเป็นตัวพิมพ์เล็ก ปรับยูนิโค้ดเป็น NFC) · แต่ละกลุ่มแสดงจำนวนรายงานที่ยังไม่หมดอายุ รวมถึงความลึก เวลา และระดับความรุนแรงของรายงานล่าสุด · IP เดียวกันส่งจุดเดียวกันซ้ำ รายงานใหม่**แทนที่**รายงานเดิม จึงนับเป็น 1 (รายงานที่ส่งทีหลังชนะเสมอ) |

### วัดผล: เกณฑ์ว่างานเสร็จ (ทุกข้อตรวจจาก test ได้)

1. `POST /reports` ที่ข้อมูลถูกต้อง ได้ status `201`
2. ข้อมูลผิดได้ status `400` พร้อมชื่อช่องที่ผิด ได้แก่ เขตไม่อยู่ใน 12 เขต · ความลึกไม่อยู่ใน 1–200 · เวลาไม่มีเขตเวลา · เวลาอยู่นอกช่วงที่รับ · จุดสังเกตว่างหรือยาวเกิน 100 code point
3. ส่งเกินโควตาได้ status `429` (ค่าเริ่มต้น 5 ครั้งต่อ IP ต่อ 10 นาที)
4. `GET /districts/:id` มีส่วน `reports` แยกจาก `stations` มีป้าย "ยังไม่ยืนยัน" และมี `NOTICE`
5. รายงานที่หมดอายุแล้วไม่แสดง
6. IP ไม่ปรากฏทั้งในคำตอบของ API และใน log
7. `npm test` และ `npm run lint` ผ่าน · test เดิมใน `tests/` ยังผ่านโดยไม่ต้องแก้

ตัววัดจากการใช้งานจริง เช่น จำนวนรายงานต่อวัน หรือเวลาตั้งแต่น้ำเริ่มท่วมจนมีรายงานแรก ยังวัดไม่ได้ เพราะ repo นี้ใช้ข้อมูลสมมติและไม่มีผู้ใช้จริง ดู Open questions

## Constraints

### ความปลอดภัยและข้อมูลส่วนบุคคล

- **ห้ามส่งรายงานทดสอบไปที่ระบบจริง** เช่น ROOP TAN JAI Flood Watch (`flood-api.rooptanjai.com`) ใช้ได้แค่ GET ห้าม POST ห้าม DELETE เพราะคนใช้แผนที่นั้นตัดสินใจจริงในช่วงน้ำท่วม
- IP เป็นข้อมูลส่วนบุคคลตาม PDPA จึงใช้ได้แค่นับโควตาและจับรายงานซ้ำ ในหน่วยความจำเท่านั้น ห้ามเก็บลงในรายงาน ห้ามส่งออกใน API และห้ามลง log
- ไม่เก็บพิกัด ไม่เก็บเบอร์โทร และไม่เก็บชื่อคนส่ง
- จุดสังเกตเป็นข้อความที่ผู้ใช้พิมพ์เอง ต้องจำกัดความยาว และส่งกลับเป็นข้อมูล JSON เท่านั้น ห้ามนำไปประกอบเป็น HTML หรือคำสั่งใดๆ
- server ปัจจุบันอ่าน body โดยไม่จำกัดขนาด (`src/server.ts`) ต้องจำกัดขนาด body ก่อนเปิดรับ `POST`
- ทุกคำตอบ `2xx` ของ API ต้องมี `NOTICE` (คำตอบ error ไม่มีข้อมูลน้ำให้ใครใช้ตัดสินใจ จึงไม่ต้องมี) ว่าเป็นตัวอย่างเพื่อการเรียน ไม่ใช่ประกาศเตือนภัยทางการ

### งบ

- ไม่เพิ่ม dependency ที่ใช้ตอนรัน และไม่ใช้บริการภายนอกที่เสียเงิน ใช้แค่สิ่งที่มากับ Node 22 และ devDependencies ที่มีอยู่

### กฎของ repo

- ความลึกเป็นจำนวนเต็มหน่วยเซนติเมตร
- เวลาเก็บเป็น UTC แสดงเป็นเวลากรุงเทพฯ (+07:00)
- routing อยู่ใน `handle()` ที่ไม่ผูกกับ `node:http` · เวลาทั้งหมดมาจาก `ctx.now` ห้ามเรียก `new Date()` ใน logic

### สิ่งที่ห้ามแตะ

- `data/stations.json` เป็นข้อมูลสถานีวัดที่บันทึกไว้ รายงานจากประชาชนห้ามปนลงไฟล์นี้
- พฤติกรรมเดิมของ `GET /districts` และ `GET /districts/:id` ต้องคงเดิม เพิ่มได้เฉพาะส่วน `reports`
- test เดิมใน `tests/` ห้ามแก้ให้ผ่าน
- รายชื่อ 12 เขตใน `src/districts.ts` ไม่เพิ่ม ไม่ลด ในงานนี้
